# Word/WPS 目标编辑器验收

生成的 DOCX 主要面向教师使用的 Microsoft Word 或 WPS 文字。两者的字体替代、表格分页、行高和兼容模式处理可能与 LibreOffice 不同，因此最终版式以用户指定的目标编辑器为准。

## 编辑器选择

1. 用户指定 Word 或 WPS 时使用其指定编辑器。
2. 用户未指定时，优先使用本机已安装且正在使用的 Word；没有 Word 再使用 WPS。
3. 两者均不可用时才使用 `verify_docx.py` 做 LibreOffice 降级预览，并明确报告尚未完成目标编辑器验收。

## Computer Use 流程

当环境提供 Computer Use 时，直接控制目标编辑器：

1. 使用应用名称获取状态；Word 使用 `Microsoft Word`，WPS 使用实际显示名称。若名称失败，再查询应用列表取得标识。
2. 打开输出 DOCX 的绝对路径。优先从编辑器“打开”界面或最近文档进入，不通过另一个编辑器转换文件。
3. 等待文档完成重排，确认处于打印布局。记录标题栏中的兼容模式提示、状态栏页数及可见的编辑器版本。
4. 从第一页开始逐页浏览。每次页面变化后重新读取应用状态并查看截图，不复用旧的界面元素编号。
5. 检查封面、进度表、每个课次首页、跨页表格接缝、反思区及末页；对长文档仍须覆盖每一页，不能只抽查首尾页。
6. 检查中文是否缺字，表格或文本是否裁切/重叠，重复表头是否正常，是否出现异常空白页、孤立标题或孤立反思页，并记录目标编辑器显示的总页数。
7. 如果 Word/WPS 提示转换格式、修复文档、替换字体或保存更改，只读取提示并报告；未经用户授权不得保存或覆盖原文件。
8. 修复生成逻辑后关闭旧预览，重新生成到新文件并再次从第一页验收。

长文档可从目标编辑器原生导出 PDF 到新的临时路径，再把每页转为图片逐页检查。这仍属于 Word/WPS 排版证据；记录导出来源，核对 PDF 页数与编辑器稳定页数一致，不能用 LibreOffice 转换的 PDF 冒充。导出副本不得覆盖 DOCX 或接受格式升级；遇到联机转换或上传提示时停止，不默认把文件发往云端。

## 结果分级

- **目标编辑器通过**：在用户指定或按规则选择的 Word/WPS 中完成逐页检查，未发现阻断问题。
- **目标编辑器失败**：Word/WPS 中存在缺字、断表、裁切、异常分页等问题。应修复后重验。
- **仅降级预览**：只完成 LibreOffice/PDF 检查。可用于开发回归，但不能声称 Word/WPS 高保真通过。
- **未验收**：没有可用目标编辑器，也未能完成降级预览。

Word 与 WPS 的结果不一致时，以用户实际交付环境为准，并把差异写入交付说明；不要为了让 LibreOffice 通过而牺牲 Word/WPS 的正常显示。

## 证据与判定边界

- AX 中 `Page N content` 为空只表示“疑似空页”，不能直接判定为空白页；页眉、表格延续和虚拟化都可能导致文本树为空。
- 总页数应连续读取两次且保持一致。逐页截图必须覆盖 `1..N`，缺页或页数中途变化时验收不完整。
- AX 可以记录文件路径、应用名、兼容模式、状态栏页数和访问过的页；缺字、裁切、重叠、表格接缝、异常留白仍必须看截图。
- 重复表头须从完整页面图像确认；截屏未覆盖页顶或 OOXML 中存在 `tblHeader`，均不足以判定成功或失败。
- 只有每页均有截图、全部适用视觉检查通过、没有修复/字体替换/格式转换阻断提示且未保存兼容性改写时，才能标记“目标编辑器通过”。
