# 教案专业写实与去 AI 化编写指南

> 本指南用于所有学科、学段（中职、高职、普高、中小学等）教学设计方案的内容撰写与审校。
> **核心底线**：教案靠具体教学动作、真实操作命令、可观测的行为结果与真实师生卡点站住，绝不用假大空的教育口号、套话和重复解释灌字数。

---

## 第一部分：中文文本硬核去 AI 禁令（模型腔清零）

大模型写公文和方案时极易陷入固有姿态。以下禁令在生成教案正文时必须 100% 严格执行：

### 1. 严禁翻案句与抬价体
逐句自检，严禁先立一个假想问题再推翻抬价。命中任何一项一律拆回正面陈述：
- 🚫 **字面翻案**：“不是 A，而是 B。” / “并非 A，而是 B。” / “不在于 A，而在于 B。”
- 🚫 **换字变形**：“与其说 A，倒不如讲 B。” / “看似 A，实则 B。” / “表面上是 A，其实是 B。”
- 🚫 **抬价体**：“真正关键的不是……而是……” / “A 不重要，重要的是 B。” / “真正决定成败的从来不是……”
- 💡 **改写方式**：直接正面陈述事实和要求。例如将“本节课的关键并非记住命令，而是掌握权限逻辑”改写为“本节课重点训练学生依据权限分配表独立推演读写执行权限”。

### 2. 严禁名词化虚词与假动作
将大模型惯用的被动化、名词化虚词还原为教师和学生的真实动作：
- 🚫 严禁：“进行了详细讲解” ➔ ✅ 改为：“演示……”、“分步拆解……”
- 🚫 严禁：“实现了对……的掌握” ➔ ✅ 改为：“能在 5 分钟内独立完成……”
- 🚫 严禁：“起到了巩固强化的作用” ➔ ✅ 改为：“通过 3 组梯度练习检验……”
- 🚫 严禁：“完成了相关的任务布置” ➔ ✅ 改为：“分发任务工单，要求……”

### 3. 严禁商业与模型黑话
彻底清除以下无意义的空泛词汇：
- 🚫 严禁：“赋能”、“闭环”、“底层逻辑”、“维度矩阵”、“深层机理”、“协同演进”、“从某种意义上说”
- 🚫 严禁洞察路标：“值得注意的是……”、“需要指出的是……”、“毋庸置疑的是……”

### 4. 严禁机械同构排比
严禁为了凑节奏连续使用 3 句以上同句式排比套话（如“让学生在探索中发现、在实践中感悟、在反思中升华”），直接删减并替换为具体实操步骤。

## 第二部分：教学设计事实化与行为动词法则（Pedagogical Realism）

### 1. 教学目标必须具体且可考核（ABCD 目标法）
严禁出现无法观测、无法考核的形容词。必须指明具体的知识点、工具、参数和动作标准：

| 目标维度 | ❌ 假大空写法（模型腔） | ✅ 真实一线优秀教案写法（写实规范） |
| :--- | :--- | :--- |
| **知识目标** | “深入理解操作系统权限的深层原理与重要性。” | “能准确说出 `rwx` 三种权限的八进制数值对应关系，并能画出用户-组-其他人的三级权限结构图。” |
| **能力目标** | “提高学生计算机实操能力与综合应用素养。” | “能在 Linux 终端使用 `chmod 755` 和 `chown` 正确设置文件权限，并能独立排查 Permission Denied 报错。” |
| **素养目标** | “培养学生严谨的科学精神与良好的道德品质。” | “在执行关键文件修改前养成主动备份与检查当前工作路径的规范工程习惯。” |

### 2. 教学过程师生活动现场写实（拒绝假对话与假巡堂）
每一教学环节必须包含真实动作，拒绝任何形式的虚假互动：

- 🚫 **严禁假互动对白**：
  - 错误示例：`师：“同学们，大家听明白了吗？” 生：“听明白了！”`
  - 正确做法：教师设计具体设问或操作卡点，例如：`教师在终端执行修改属主命令并故意省略 -R 参数，提问：“为何子目录内的文件权限未发生改变？” 引导学生观察目录递归参数。`
- 🚫 **严禁假巡堂套话**：
  - 错误示例：`教师巡视指导，学生自主探究练习。`
  - 正确做法：明确写出学生的练习卡点与教师的巡检核验点：`学生对照工单步骤 1-3 独立完成虚拟网卡配置；教师巡视重点检查 IP 地址与子网掩码的输入格式，纠正 2-3 名将英文句点误输为中文句号的常见错误。`

### 3. 教学重难点具象化
- **重点**：必须是本节课的核心知识与技能主干（如“核心命令的语法格式与常用参数组合”）。
- **难点**：必须是学生在认知或实操中一定会遇到的阻碍或易混淆点（如“相对路径与绝对路径在不同当前目录下的相对位移计算”）。

### 4. 结构化板书设计（拒绝 PPT 目录复读机）
板书设计必须体现结构化思维、逻辑关系或语法框图，严禁仅将 PPT 标题 1、2、3 复制一遍：
- 采用树状结构、对比表格、流程箭头或语法参数分解图；
- 突出本课核心操作流程与口诀。

### 5. 课后作业产出化
- 严禁：“课后认真复习今天所学内容，预习下一节”；
- 必须包含具体的交付物标准：“完成项目工单第 4 题，提交包含创建目录结构与权限设置结果的终端截图（须包含本机学号用户名）”。

## 第三部分：课时设计自检清单（交付前 5 问）

在生成最终教案 JSON 数据前，对每一个课时进行自检：
1. **看动作**：师生活动里是否每个环节都有具体的命令/案例/步骤，还是在用虚词打太极？
2. **看语言**：全文是否已彻底剔除“不是……而是……”、“进行了……”、“值得注意的是”等模型腔？
3. **看卡点**：是否预设了学生在实操中最容易踩的坑和报错？
4. **看产出**：作业和课堂评价是否有清晰可查的交付物？
5. **看时间**：45、90、135 分钟或其他课时的环节时间是否合计正确，是否为演示、练习、反馈和转场留出真实时间？实践比例应由课型、目标和用户要求决定；技能实训课通常需要让学生操作占主要时间，但不设跨学科固定比例。
6. **看资源**：活动是否只使用用户明确提供的设备、软件、网络、账号和材料？不得默认有机房，也不得默认无机房；条件不足时给出不改变核心目标的替代方案并标明适用条件。
7. **看差异**：常见卡点出现时是否有分步提示、示例或补救任务？提前完成的学生是否有适量拓展，而不是机械增加作业量？
